## ROS 2 میں سروسز کو سمجھنا

ROS 2 میں سروسز ایک درخواست-جواب مواصلاتی نمونہ فراہم کرتے ہیں، جو ٹوپکس کے غیر ہم وقت، شائع کنندہ-سبسکرائب ماڈل سے بنیادی طور پر مختلف ہے۔ سروس بیسڈ مواصلت میں، ایک کلائنٹ ایک سروس سرور کو ایک درخواست بھیجتا ہے، اور سرور درخواست کو عمل میں لاتا ہے اور ایک جواب لوٹاتا ہے۔ یہ نمونہ ہم وقت ہے، جس کا مطلب ہے کہ کلائنٹ جاری رکھنے سے پہلے جواب کا انتظار کرتا ہے۔

### ہم وقت درخواست-جواب نمونہ

سروس مواصلاتی نمونہ مندرجہ ذیل کے ذریعے خصوصیات یافتہ ہے:
- **درخواست**: کلائنٹ کے ذریعے سروس سرور کو بھیجا گیا
- **جواب**: سرور کے ذریعے کلائنٹ کو لوٹایا گیا
- **بلاکنگ**: کلائنٹ عام طور پر جاری رکھنے سے پہلے جواب کا انتظار کرتا ہے
- **ایک سے ایک**: ایک واحد درخواست ایک واحد جواب پیدا کرتی ہے

### کلائنٹ-سرور معماری

ROS 2 سروس معماری میں:
- **سروس سرور**: سروس منطق نافذ کرتا ہے اور درخواستوں کا جواب دیتا ہے
- **سروس کلائنٹ**: سرور کو درخواستیں بھیجتا ہے اور جوابات وصول کرتا ہے
- **سروس انٹرفیس**: `.srv` فائلز کا استعمال کرتے ہوئے درخواستوں اور جوابات کی ساخت کی وضاحت کرتا ہے

### سروسز کو ٹوپکس کے مقابلے میں کب استعمال کرنا ہے

جب استعمال کریں:
- جب آپ کو ضمانت شدہ ترسیل اور جواب کی ضرورت ہو
- جب کام میں ایک واضح درخواست-جواب کی نوعیت ہو
- جب کلائنٹ کو جاری رکھنے سے پہلے نتیجہ کا انتظار کرنے کی ضرورت ہو
- جب آپ کو کنفیگریشن یا کارروائیاں شروع کرنے جیسے ایک وقت کے کام انجام دینے کی ضرورت ہو

جب ٹوپکس استعمال کریں:
- جب آپ کو مسلسل ڈیٹا اسٹریم کرنے کی ضرورت ہو
- جب آپ کو ضمانت شدہ ترسیل کی ضرورت نہ ہو
- جب متعدد سبسکرائیبرز کو ایک ہی ڈیٹا کی ضرورت ہو
- جب آپ غیر جڑی ہوئی، غیر ہم وقت مواصلت چاہتے ہوں

### سروس انٹرفیسز اور پیغام کی اقسام

سروس انٹرفیسز `.srv` فائلز میں وضاحت کی جاتی ہیں جو درخواست اور جواب پیغام کی اقسام کی وضاحت کرتی ہیں۔ مثال کے طور پر، ایک `AddTwoInts.srv` فائل مندرجہ ذیل پر مشتمل ہو سکتی ہے:

```
int64 a
int64 b
---
int64 sum
```

`---` کے اوپر کا حصہ درخواست پیغام کی وضاحت کرتا ہے، اور نیچے والا حصہ جواب پیغام کی وضاحت کرتا ہے۔

## سروس معماری اور نفاذ

### سروس تعریف فائلیں (.srv)

سروس تعریف فائلیں سروس کلائنٹس اور سرورز کے درمیان انٹرفیس کی وضاحت کرتی ہیں۔ ان فائلز کو ROS 2 پیکج کی `srv/` ڈائریکٹری میں رکھا جاتا ہے اور ایک مخصوص فارمیٹ کو فالو کرتی ہیں:

```
# درخواست پیغام فیلڈز
field_type field_name
field_type field_name
---
# جواب پیغام فیلڈز
field_type field_name
field_type field_name
```

ہر سروس تعریف `---` کے ذریعے الگ کی گئی دو حصوں پر مشتمل ہوتی ہے۔ پہلا حصہ درخواست پیغام فیلڈز کی وضاحت کرتا ہے، اور دوسرا حصہ جواب پیغام فیلڈز کی وضاحت کرتا ہے۔

### سروس سرورز اور کلائنٹس

- **سروس سرور**: سروس منطق کا نفاذ کرتا ہے۔ یہ ایک کال بیک فنکشن کو رجسٹر کرتا ہے جسے درخواست آنے پر متحرک کیا جاتا ہے۔
- **سروس کلائنٹ**: سروس سرور کو درخواستیں بھیجتا ہے اور جوابات وصول کرتا ہے۔ یہ مواصلاتی تفصیلات کو پارلین طور پر ہینڈل کرتا ہے۔

### سروسز میں خامی ہینڈلنگ

سروس نفاذ کو ممکنہ خامیوں کو نرمی سے ہینڈل کرنا چاہیے:
- غلط درخواست پیرامیٹرز
- سروس کی عدم دستیابی
- نیٹ ورک ٹائم آؤٹس
- اندرونی پروسیسنگ کی خامیاں

### ٹائم آؤٹ اور دوبارہ کوشش کے میکانزم

کلائنٹس ٹائم آؤٹ اور دوبارہ کوشش کے میکانزم نافذ کر سکتے ہیں تاکہ سروس کی عدم دستیابی کو ہینڈل کیا جا سکے:
- سروس کالز کے لیے ٹائم آؤٹس سیٹ کرنا
- ایکسپونینشل بیک آف کے ساتھ دوبارہ کوشش کا منطق نافذ کرنا
- جب سروسز دستیاب نہ ہوں تو فال بیک سلوک فراہم کرنا

## C++ میں سروسز تخلیق کرنا

### سروسز کے لیے rclcpp کا استعمال

`rclcpp` لائبریری C++ انٹرفیس فراہم کرتی ہے سروسز تخلیق کرنے کے لیے۔ اہم کلاسز مندرجہ ذیل ہیں:
- `rclcpp::Service`: ایک سروس سرور کی نمائندگی کرتا ہے
- `rclcpp::Client`: ایک سروس کلائنٹ کی نمائندگی کرتا ہے
- `.srv` فائلز سے تیار کردہ سروس قسم کی مخصوص کلاسز

### سروس کال بیکس کی وضاحت کرنا

سروس کال بیکس ایک درخواست وصول کرتے ہیں اور ایک جواب لوٹاتے ہیں:

```cpp
void handle_add_two_ints(
  const std::shared_ptr<rmw_request_id_t> request_header,
  const std::shared_ptr<example_interfaces::srv::AddTwoInts::Request> request,
  std::shared_ptr<example_interfaces::srv::AddTwoInts::Response> response)
{
  RCLCPP_INFO(rclcpp::get_logger("rclcpp"), "اندرونی درخواست\na: %ld, b: %ld",
    request->a, request->b);
  response->sum = request->a + request->b;
}
```

### سروس سرورز اور کلائنٹس تخلیق کرنا

سروس سرور:
```cpp
auto service = this->create_service<example_interfaces::srv::AddTwoInts>(
  "add_two_ints", std::bind(&MinimalService::handle_add_two_ints, this,
  std::placeholders::_1, std::placeholders::_2, std::placeholders::_3));
```

سروس کلائنٹ:
```cpp
auto client = this->create_client<example_interfaces::srv::AddTwoInts>("add_two_ints");
```

### سروس نوڈس کی تعمیر اور کمپائل کرنا

آپ کے `CMakeLists.txt` میں، آپ کو یہ کرنا ہوگا:
- پیکج تلاش کریں جس میں سروس تعریف ہے
- سروس پیغامات تیار کریں
- ضروری لائبریریز کے خلاف لنک کریں

```cmake
find_package(example_interfaces REQUIRED)
rosidl_generate_interfaces(${PROJECT_NAME}
  "srv/AddTwoInts.srv"
  DEPENDENCIES builtin_interfaces
)
ament_target_dependencies(your_node_name
  rclcpp
  example_interfaces
)
```

## Python میں سروسز تخلیق کرنا

### سروسز کے لیے rclpy کا استعمال

`rclpy` لائبریری Python انٹرفیس فراہم کرتی ہے سروسز تخلیق کرنے کے لیے۔ اہم اجزاء مندرجہ ذیل ہیں:
- `rclpy.service.Service`: ایک سروس سرور کی نمائندگی کرتا ہے
- `rclpy.client.Client`: ایک سروس کلائنٹ کی نمائندگی کرتا ہے
- `.srv` فائلز سے تیار کردہ سروس قسم کی مخصوص کلاسز

### سروس کال بیکس کی وضاحت کرنا

Python میں، سروس کال بیکس سادہ ہوتے ہیں:

```python
def add_two_ints_callback(self, request, response):
    response.sum = request.a + request.b
    self.get_logger().info(f'درخواست موصول ہوئی: {request.a} + {request.b} = {response.sum}')
    return response
```

### سروس سرورز اور کلائنٹس تخلیق کرنا

سروس سرور:
```python
self.srv = self.create_service(
  AddTwoInts, 'add_two_ints', self.add_two_ints_callback)
```

سروس کلائنٹ:
```python
self.cli = self.create_client(AddTwoInts, 'add_two_ints')
```

Python سروس نوڈس کو براہ راست چلایا جا سکتا ہے یا پیکج مینیفیسٹ میں ایکسیکوٹیبلس کے طور پر رجسٹر کیا جا سکتا ہے۔

## ROS 2 میں ایکشنز کو سمجھنا

ROS 2 میں ایکشنز طویل مدتی کاموں کے لیے ایک مواصلاتی نمونہ فراہم کرتے ہیں جن میں انجام کے دوران فیڈ بیک کی ضرورت ہو سکتی ہے اور کام کو روکنے یا منسوخ کرنے کی صلاحیت ہو۔ خدمات کے برعکس، جو فوری جوابات فراہم کرتے ہیں، ایکشنز ان کاموں کے لیے ڈیزائن کیے گئے ہیں جن میں مکمل ہونے میں کافی وقت لگ سکتا ہے۔

### فیڈ بیک کے ساتھ طویل مدتی کام

ایکشنز ان کاموں کے لیے بہترین ہیں جو:
- مکمل ہونے میں کافی وقت لیتے ہیں
- انجام کے دوران فراہم کیے گئے فیڈ بیک سے فائدہ اٹھاتے ہیں
- منسوخ یا روکنے کی ضرورت ہو سکتی ہے
- مقصد کے مطابق پیرامیٹرز کی ضرورت ہوتی ہے

### مقصد، فیڈ بیک، اور نتیجہ کے تصورات

ایکشنز تین اہم پیغام کی اقسام میں شامل ہیں:
- **مقصد**: یہ وضاحت کرتا ہے کہ ایکشن کو کیا کرنا چاہیے
- **فیڈ بیک**: انجام کے دوران اسٹیٹس اپ ڈیٹس فراہم کرتا ہے
- **نتیجہ**: ایکشن کا حتمی نتیجہ مشتمل ہوتا ہے

### ایکشنز کو خدمات کے مقابلے میں کب استعمال کرنا ہے

جب استعمال کریں:
- جب کام میں کافی وقت لگتا ہے
- جب آپ کو انجام کے دوران فیڈ بیک کی ضرورت ہو
- جب کام کو روکا یا منسوخ کیا جا سکے
- جب آپ کو کام کی پیشرفت کو ٹریک کرنے کی ضرورت ہو

جب خدمات استعمال کریں:
- جب کام جلدی مکمل ہو جاتا ہے
- جب آپ کو ایک سادہ درخواست-جواب نمونہ چاہیے
- جب روک تھام یا فیڈ بیک کی ضرورت نہ ہو

### ایکشن انٹرفیسز اور پیغام کی اقسام

ایکشن انٹرفیسز `.action` فائلز میں وضاحت کی جاتی ہیں جو مقصد، نتیجہ، اور فیڈ بیک پیغام کی اقسام کی وضاحت کرتی ہیں:

```
# مقصد کی وضاحت
int32 order
---
# نتیجہ کی وضاحت
int32[] sequence
---
# فیڈ بیک کی وضاحت
int32[] sequence
```

## ایکشن معماری اور نفاذ

### ایکشن تعریف فائلیں (.action)

ایکشن تعریف فائلیں ایکشنز کے لیے انٹرفیس کی وضاحت کرتی ہیں اور `---` کے ذریعے الگ کی گئی تین حصوں پر مشتمل ہوتی ہیں:
- **مقصد**: ایکشن شروع کرنے کے لیے پیرامیٹرز کی وضاحت کرتا ہے
- **نتیجہ**: مکمل ہونے والے ایکشن کا آؤٹ پٹ وضاحت کرتا ہے
- **فیڈ بیک**: جاری اسٹیٹس اپ ڈیٹس کی وضاحت کرتا ہے

### ایکشن سرورز اور کلائنٹس

- **ایکشن سرور**: ایکشن منطق نافذ کرتا ہے، مقاصد کا نظم کرتا ہے، فیڈ بیک فراہم کرتا ہے، اور نتائج لوٹاتا ہے
- **ایکشن کلائنٹ**: سرور کو مقاصد بھیجتا ہے، فیڈ بیک وصول کرتا ہے، اور نتائج حاصل کرتا ہے

### مقصد کی روک تھام اور منسوخی

ایکشنز کام کو روکنے کے دو طریقے سپورٹ کرتے ہیں:
- **روک تھام**: موجودہ مقصد کو ایک نئے کے ساتھ تبدیل کریں
- **منسوخی**: موجودہ مقصد کے کام کو مکمل طور پر روک دیں

### فیڈ بیک میکانزم

ایکشن سرورز انجام کے دوران جاری طور پر فیڈ بیک پیغامات کلائنٹس کو بھیجتے ہیں، جس سے کلائنٹس کو پیشرفت کو مانیٹر کرنے اور جاری اسٹیٹس کی بنیاد پر فیصلے کرنے کی اجازت ملتی ہے۔

## C++ میں ایکشنز تخلیق کرنا

### ایکشنز کے لیے rclcpp کا استعمال

`rclcpp` لائبریری ایکشن سپورٹ فراہم کرتی ہے مندرجہ ذیل کے ذریعے:
- `rclcpp_action::Server`: ایک ایکشن سرور کی نمائندگی کرتا ہے
- `rclcpp_action::Client`: ایک ایکشن کلائنٹ کی نمائندگی کرتا ہے
- `.action` فائلز سے تیار کردہ ایکشن قسم کی مخصوص کلاسز

### ایکشن کال بیکس کی وضاحت کرنا

ایکشن کال بیکس مقصد کی قبولیت، انجام، اور منسوخی کو ہینڈل کرتے ہیں:

```cpp
rclcpp_action::GoalResponse handle_goal(
  const rclcpp_action::GoalUUID & uuid,
  std::shared_ptr<const Fibonacci::Goal> goal)
{
  RCLCPP_INFO(this->get_logger(), "مقصد کی درخواست موصول ہوئی %d کے ساتھ", goal->order);
  (void)uuid;
  return rclcpp_action::GoalResponse::ACCEPT_AND_EXECUTE;
}

rclcpp_action::CancelResponse handle_cancel(
  const std::shared_ptr<rclcpp_action::ServerGoalHandle<Fibonacci>> goal_handle)
{
  RCLCPP_INFO(this->get_logger(), "مقصد کو منسوخ کرنے کی درخواست موصول ہوئی");
  (void)goal_handle;
  return rclcpp_action::CancelResponse::ACCEPT;
}

void handle_accepted(const std::shared_ptr<rclcpp_action::ServerGoalHandle<Fibonacci>> goal_handle)
{
  using namespace std::placeholders;
  // اسے ایکسیکیوٹر کو بلاک کرنے سے بچنے کے لیے جلدی سے واپس آنا چاہیے، تو ایک نئی تھریڈ شروع کریں
  std::thread{std::bind(&MinimalActionServer::execute, this, _1), goal_handle}.detach();
}
```

- `.action` فائلز سے تیار کردہ ایکشن قسم کی مخصوص کلاسز

### ایکشن کال بیکس کی وضاحت کرنا

Python میں ایکشن کال بیکس C++ کے مشابہ ہیں لیکن زیادہ پائی تھونک نقطہ نظر کے ساتھ:

```python
async def execute_callback(self, goal_handle):
  self.get_logger().info('مقصد کا انجام جاری ہے...')

  feedback_msg = Fibonacci.Feedback()
  feedback_msg.sequence = [0, 1]

  for i in range(1, goal_handle.request.order):
      if goal_handle.is_cancel_requested:
          goal_handle.canceled()
          self.get_logger().info('مقصد منسوخ ہو گیا')
          return Fibonacci.Result()

      feedback_msg.sequence.append(feedback_msg.sequence[i] + feedback_msg.sequence[i-1])
      self.get_logger().info(f'فیڈ بیک شائع کر رہے ہیں: {feedback_msg.sequence}')

      goal_handle.publish_feedback(feedback_msg)
      await asyncio.sleep(1)  # کام کی شبیہہ

  goal_handle.succeed()
  result = Fibonacci.Result()
  result.sequence = feedback_msg.sequence
  self.get_logger().info(f'نتیجہ واپس کر رہے ہیں: {result.sequence}')

  return result
```

- **ایکشنز**: پیچیدہ اسٹیٹ مینجمنٹ، فیڈ بیک کی صلاحیت، زیادہ اوور ہیڈ
