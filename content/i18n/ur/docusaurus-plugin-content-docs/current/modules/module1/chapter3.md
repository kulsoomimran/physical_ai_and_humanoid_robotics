## ROS 2 نوڈس کو سمجھنا

نوڈس ROS 2 ایپلیکیشنز کے بنیادی بلڈنگ بلاکس ہیں۔ ہر نوڈ ایک آزاد عمل ہے جو تشریح کرتا ہے اور ٹوپکس، سروسز، یا ایکشنز کے ذریعے دیگر نوڈس کے ساتھ مواصلت کرتا ہے۔ نوڈس فعلیت کو احاطہ کرتے ہیں اور پیچیدہ روبوٹکس سسٹم کو قابل انتظام اجزاء میں منظم کرنے کا طریقہ فراہم کرتے ہیں۔

### ROS 2 میں نوڈس کی تعریف اور کردار

ROS 2 میں، ایک نوڈ ایک عمل ہے جو تشریح کرتا ہے اور دیگر نوڈس کے ساتھ مواصلت کرتا ہے۔ ROS 1 کے برعکس، جہاں نوڈس کو ایک مرکزی ماسٹر کی ضرورت تھی، ROS 2 نوڈس DDS مڈل ویئر کا استعمال کرتے ہوئے براہ راست مواصلت کرتے ہیں۔ یہ غیر مرکزی نقطہ نظر مضبوطی اور قابل توسیعیت میں بہتری لاتا ہے۔

نوڈس عام طور پر:
- شائع کنندگان اور/یا سبسکرائیبرز کو شامل کرتے ہیں
- سروسز یا ایکشن سرورز فراہم کرتے ہیں
- پیرامیٹرز ہوتے ہیں جن کی تشکیل کی جا سکتی ہے
- بہتر تنظیم کے لیے نیم سپیس میں منظم کیے جا سکتے ہیں

### ROS 1 سے نوڈس کیسے مختلف ہیں

سب سے اہم فرق یہ ہے کہ ROS 2 نوڈس کو مرکزی ماسٹر کی ضرورت نہیں ہوتی۔ بجائے اس کے، وہ ایک دوسرے کو تلاش کرنے کے لیے DDS دریافت کے میکانزم کا استعمال کرتے ہیں۔ یہ فراہم کرتا ہے:
- بہتر خرابی برداشت (کوئی واحد نقص کی جگہ نہیں)
- بہتر اسکیل ایبلٹی
- متعدد روبوٹ سسٹم کی حمایت
- بہتر سیکیورٹی کی صلاحیتیں

### نوڈ نامزد اور نیم سپیسز

نوڈ نامزد کو ROS 2 ڈومین کے اندر منفرد ہونا چاہیے۔ نیم سپیسز نوڈس کو سلسلہ وار طور پر منظم کرنے کا طریقہ فراہم کرتے ہیں، ڈائریکٹری ڈھانچوں کی طرح۔ نیم سپیسز نامزد تنازعات سے بچنے اور متعلقہ نوڈس کی منطقی گروپنگ فراہم کرتے ہیں۔

### نوڈ کمپوزیشن بمقابلہ تقسیم شدہ نوڈس

ROS 2 تقسیم شدہ نوڈس (الگ الگ عمل) اور نوڈ کمپوزیشن (ایک ہی عمل میں متعدد نوڈس) دونوں کی حمایت کرتا ہے۔ کمپوزیشن متعدد نوڈس کے لیے نیٹ ورک اوور ہیڈ سے بچ کر کارکردگی میں بہتری لانے میں مدد دے سکتا ہے جنہیں اکثر مواصلت کی ضرورت ہوتی ہے۔

## نوڈ ساخت اور زندگی کا چکر

### نوڈ کلاس تخلیق کرنا

ایک نوڈ تخلیق کرنے کے لیے، آپ عام طور پر کلائنٹ لائبریری کے ذریعے فراہم کردہ نوڈ کلاس سے وراثت میں لیتے ہیں:

C++ میں:
```cpp
#include "rclcpp/rclcpp.hpp"

class MyNode : public rclcpp::Node
{
public:
    MyNode() : Node("my_node_name") {
        // یہاں شروعاتی کوڈ
    }
};
```

Python میں:
```python
import rclpy
from rclpy.node import Node

class MyNode(Node):
    def __init__(self):
        super().__init__('my_node_name')
        # یہاں شروعاتی کوڈ
```

### شروعات اور ترتیب

نوڈ شروعات میں عام طور پر شامل ہوتا ہے:
- شائع کنندگان اور سبسکرائیبرز کو ترتیب دینا
- ٹائمرز تخلیق کرنا
- پیرامیٹرز کا اعلان اور حصول
- سروس یا ایکشن سرورز/کلائنٹس تخلیق کرنا

### نوڈ انجام اور سپننگ

نوڈس کو "سپن" کرنا چاہیے تاکہ کال بیکس کو عمل میں لایا جا سکے اور مواصلت کو ہینڈل کیا جا سکے۔ سپن فنکشن مسلسل چلتا ہے، جب پیغامات آتے ہیں یا ٹائمرز ختم ہوتے ہیں تو کال بیکس انجام دیتے ہیں۔

### صاف کرنا اور بند کرنا

جب ایک نوڈ بند ہوتا ہے، تو اسے وسائل کو مناسب طریقے سے صاف کرنا چاہیے، ٹائمرز منسوخ کرنا چاہیے، اور مواصلاتی چینلز سے منقطع ہونا چاہیے۔

## ٹوپکس اور شائع کنندگان

ٹوپکس نامزد بس ہیں جن کے ذریعے نوڈس پیغامات کا تبادلہ کرتے ہیں۔ ٹوپک بیسڈ مواصلت غیر ہم وقت ہے اور ایک شائع کنندہ-سبسکرائب نمونہ پر عمل کرتی ہے۔

### ٹوپک نامزد کنونشنز

ٹوپک نامزد کو ان کنونشنز کا پیروی کرنا چاہیے:
- lowercase حروف، اعداد، اور انڈر سکور استعمال کریں
- الفاظ کو انڈر سکور سے الگ کریں
- وضاحتی نام استعمال کریں جو مواد کی وضاحت کرتے ہیں
- مناسب وقت پر نیم سپیسز کے ساتھ منظم کریں

مثالیں: `/sensor_data/laser_scan`, `/robot_status/joint_states`, `/cmd_vel`

### شائع کنندگان تخلیق کرنا

شائع کنندگان ٹوپکس کو پیغامات بھیجتے ہیں۔ ایک شائع کنندہ تخلیق کرتے وقت، آپ پیغام کی قسم اور QoS ترتیبات کی وضاحت کرتے ہیں:

C++:
```cpp
auto publisher = this->create_publisher<std_msgs::msg::String>("topic_name", 10);
```

Python:
```python
publisher = self.create_publisher(String, 'topic_name', 10)
```

### پیغامات شائع کرنا

پیغام شائع کرنے کے لیے، مناسب پیغام کی قسم تخلیق کریں، اسے ڈیٹا کے ساتھ بھریں، اور شائع کا طریقہ کال کریں:

C++:
```cpp
auto message = std_msgs::msg::String();
message.data = "ہیلو، دنیا!";
publisher->publish(message);
```

Python:
```python
msg = String()
msg.data = 'ہیلو، دنیا!'
publisher.publish(msg)
```

### پیغام کی اقسام اور انٹرفیسز

ROS 2 `std_msgs`, `geometry_msgs`, اور `sensor_msgs` جیسے پیکجز میں معیاری پیغام کی اقسام فراہم کرتا ہے۔ آپ `.msg` فائلز کا استعمال کرتے ہوئے اپنی مرضی کی پیغام کی اقسام بھی تعریف کر سکتے ہیں۔

## سبسکرائیبرز

سبسکرائیبرز ٹوپکس سے پیغامات وصول کرتے ہیں اور انہیں کال بیک فنکشنز کے ذریعے عمل میں لاتے ہیں۔

### سبسکرائیبرز تخلیق کرنا

ایک سبسکرائیبر تخلیق کرنے کے لیے، پیغام کی قسم، ٹوپک نام، کال بیک فنکشن، اور QoS ترتیبات کی وضاحت کی ضرورت ہے:

C++:
```cpp
auto subscription = this->create_subscription<std_msgs::msg::String>(
    "topic_name",
    10,
    [this](const std_msgs::msg::String::SharedPtr msg) {
        RCLCPP_INFO(this->get_logger(), "وصول ہوا: '%s'", msg->data.c_str());
    });
```

Python:
```python
subscription = self.create_subscription(
    String,
    'topic_name',
    self.listener_callback,
    10)
```

### پیغام کال بیک فنکشنز

کال بیک فنکشنز پیغامات وصول کرتے ہیں اور انہیں عمل میں لاتے ہیں۔ انہیں ہلکا پھلکا رہنا چاہیے تاکہ پیغام کی پروسیسنگ تھریڈ کو بلاک ہونے سے بچایا جا سکے۔

### ان کمنگ پیغامات کو ہینڈل کرنا

کال بیک میں، آپ وصول شدہ پیغام کو عمل میں لاسکتے ہیں، تشریح کر سکتے ہیں، اور ممکنہ طور پر نئے پیغامات شائع کر سکتے ہیں یا سروسز کال کر سکتے ہیں۔

### ایک ہی ٹوپک کے لیے متعدد سبسکرائیبرز

متعدد نوڈس ایک ہی ٹوپک کو سبسکرائب کر سکتے ہیں، اور ہر ایک کو اس ٹوپک پر شائع کردہ تمام پیغامات ملیں گے۔ یہ جڑی ہوئی، لچک دار سسٹم ڈیزائن کو فعال کرتا ہے۔

## C++ میں نوڈس تخلیق کرنا

### rclcpp کا استعمال

`rclcpp` لائبریری ROS 2 کے لیے C++ انٹرفیس فراہم کرتی ہے۔ اس میں نوڈس، شائع کنندگان، سبسکرائیبرز، سروسز، اور مزید کے لیے کلاسز شامل ہیں۔

### نوڈ کلاس وراثت

`rclcpp::Node` سے وراثت میں لیں اور نوڈ نام کے ساتھ بیس کنسرکٹر کال کریں:

```cpp
class MinimalPublisher : public rclcpp::Node
{
public:
    MinimalPublisher()
    : Node("minimal_publisher")
    {
        // نوڈ شروعات
    }
};
```

### شائع کنندہ اور سبسکرائیبر نفاذ

کنسٹرکٹر یا شروعاتی میتھڈ میں شائع کنندگان اور سبسکرائیبرز نافذ کریں:

```cpp
MinimalPublisher()
: Node("minimal_publisher")
{
    publisher_ = this->create_publisher<std_msgs::msg::String>("topic", 10);
    subscription_ = this->create_subscription<std_msgs::msg::String>(
        "topic", 10,
        [this](const std_msgs::msg::String::SharedPtr msg) {
            RCLCPP_INFO(this->get_logger(), "میں نے سنا: '%s'", msg->data.c_str());
        });
}
```

### تعمیر اور کمپائل کرنا

`ament_cmake` بلڈ سسٹم کے ساتھ CMake استعمال کریں۔ آپ کا `CMakeLists.txt` میں یہ شامل ہونا چاہیے:

```cmake
find_package(rclcpp REQUIRED)
find_package(std_msgs REQUIRED)

add_executable(my_node src/my_node.cpp)
ament_target_dependencies(my_node rclcpp std_msgs)

install(TARGETS my_node DESTINATION lib/${PROJECT_NAME})
```

## Python میں نوڈس تخلیق کرنا

### rclpy کا استعمال

`rclpy` لائبریری ROS 2 کے لیے Python انٹرفیس فراہم کرتی ہے۔ اس کو درآمد کریں اور نوڈ کلاس استعمال کریں۔

`rclpy.node.Node` سے وراثت میں لیں:

Python نوڈس کو براہ راست Python انٹرپریٹر کے ساتھ چلایا جا سکتا ہے یا setup.py یا pyproject.toml کا استعمال کرتے ہوئے ایکسیکوٹیبلس کے طور پر انسٹال کیا جا سکتا ہے۔

## ٹوپکس کے لیے کوالٹی آف سروس (QoS)

QoS پالیسیز یہ تعین کرتی ہیں کہ پیغامات کو قابل اعتمادی، durability، تاریخ، اور دیگر عوامل کے لحاظ سے کیسے ہینڈل کیا جاتا ہے۔

### قابل اعتمادی اور durability پالیسیز

- **قابل اعتمادی**: قابل اعتماد (تمام پیغامات ترسیل) یا بہترین کوشش (تیز تر، کوئی ضمانت نہیں)
- **durability**: volatile (صرف فعال سبسکرائیبرز کے لیے) یا transient local (دیر سے شامل ہونے والوں کے لیے)

### تاریخ اور گہرائی کی ترتیبات

- **تاریخ**: آخری رکھیں (پیغامات کی مقررہ تعداد) یا تمام رکھیں (تمام پیغامات، میموری محدود)
- **گہرائی**: تاریخ کی قطار میں رکھنے کے لیے پیغامات کی تعداد

### شائع کنندگان اور سبسکرائیبرز کے درمیان QoS میچ کرنا

شائع کنندگان اور سبسکرائیبرز کے پاس مؤثر طریقے سے مواصلت کرنے کے لیے مطابقت رکھنے والی QoS پالیسیز ہونی چاہیں۔ ROS 2 پالیسیز مطابقت نہ ہونے کی صورت میں متنبہ کرے گا۔

## نوڈ اور ٹوپک تشریح

### ros2 node کمانڈز استعمال کرنا

- `ros2 node list`: تمام فعال نوڈس کی فہرست
- `ros2 node info <node_name>`: نوڈ کے بارے میں تفصیلی معلومات حاصل کریں

### ros2 topic کمانڈز استعمال کرنا

- `ros2 topic list`: تمام فعال ٹوپکس کی فہرست
- `ros2 topic echo <topic_name>`: ٹوپک پر شائع کردہ پیغامات ڈسپلے کریں
- `ros2 topic info <topic_name>`: ٹوپک کے بارے میں معلومات حاصل کریں
- `ros2 topic pub <topic_name> <msg_type> <args>`: ٹوپک پر ایک پیغام شائع کریں

### ویژولائزیشن کے لیے rqt ٹولز

rqt سوٹ گرافیکل ٹولز فراہم کرتا ہے ROS 2 سسٹم کی تشریح اور ڈیبگ کرنے کے لیے، بشمول نوڈ گراف اور پیغام مانیٹرنگ۔

## بہترین مشقیں

### مناسب خامی ہینڈلنگ

نوڈ شروعات اور پیغام کی پروسیسنگ میں ممکنہ خامیوں کو ہمیشہ ہینڈل کریں۔ مناسب وقت try-catch بلاکس استعمال کریں اور معنی خیز خامی کے پیغامات فراہم کریں۔

### وسائل کا نظم

شائع کنندگان، سبسکرائیبرز، اور ٹائمرز جیسے وسائل کو مناسب طریقے سے صاف کریں۔ C++ میں RAII اصولوں اور Python میں مناسب وقت کنٹیکسٹ مینیجرز استعمال کریں۔

### نامزد کنونشنز

نوڈس، ٹوپکس، اور پیرامیٹرز کے لیے ROS نامزد کنونشنز کو فالو کریں تاکہ مسلسل معاونت یقینی بنا سکے اور تنازعات سے بچ سکے۔

### کارکردگی کے امور

- اپنی ایپلیکیشن کے لیے مناسب QoS پالیسیز استعمال کریں
- کال بیک فنکشنز میں بھاری پروسیسنگ سے بچیں
- اکثر مواصلت کرنے والے اجزاء کے لیے نوڈ کمپوزیشن استعمال کرنے پر غور کریں
- میموری کے استعمال کو مانیٹر کریں، خاص طور پر "تمام رکھیں" تاریخ کی پالیسی کے ساتھ

## خلاصہ

نوڈس اور ٹوپکس ROS 2 مواصلت کی پشت پر ہیں۔ نوڈس اور ٹوپکس کو مناسب طریقے سے تخلیق اور نظم کرنا سیکھنا ROS 2 ایپلیکیشنز تیار کرنے کے لیے انتہائی اہم ہے۔ نوڈس فعلیت کو منظم کرنے کا ایک طریقہ فراہم کرتے ہیں قابل انتظام، تقسیم شدہ اجزاء میں، جبکہ ٹوپکس نوڈس کے درمیان لچک دار، جڑی ہوئی مواصلت کو فعال کرتے ہیں۔ ٹوپکس کے ذریعے سپورٹڈ شائع کنندہ-سبسکرائب نمونہ سینسر کی ریڈنگز یا روبوٹ کی حالت کی معلومات جیسے ڈیٹا کو اسٹریم کرنے کے لیے بہترین ہے۔ مناسب QoS تشکیل اور اچھی ڈیزائن مشقیں کے ساتھ، نوڈس اور ٹوپکس قابل توسیع اور قابل اعتماد روبوٹکس سسٹم کی بنیاد بن سکتے ہیں۔

- وضاحتوں کی وضاحت اور قابلیت پڑھنے کی
- نوڈ زندگی کے چکر کا کوریج مکمل کرنا
- مناسب ساخت اور تنظیم
- کوڈ کی مثالوں اور نحو کی درستگی
